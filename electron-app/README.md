# Inkwell

A local editor for Markdown manuscripts. Open folders and files, write without distractions, recover drafts and versions, and export to PDF, DOCX, ODT, Markdown, and plain text.

## Requirements and commands

You need Node.js 22.12.0 or later and npm. Run these commands from this directory.

```bash
npm ci
npm run dev
npm run check
```

Electron downloads its official binary the first time it runs. To download it ahead of time, run `npm exec --no -- install-electron`. The build and Node/DOM tests run without launching Electron.

- `npm test` tests file operations, version history, IPC contracts, document sessions, exports, and the React/Tiptap interface.
- `npm run check` runs Prettier formatting checks, ESLint with zero warnings allowed, tests, and the production build.
- `npm run test:electron` tests native startup, sandboxing, IPC, editing, saving, and PDF export. It uses a temporary profile and files on Linux to avoid accessing user documents.
- `npm run test:packaged` runs the same test against the code and dependencies in the ASAR generated by `build:linux`.
- `npm run build:unpack` builds an unpacked app for local inspection.
- `npm run build:linux` builds x64 AppImage and deb packages with `SHA256SUMS-linux.txt`.
- `npm run build:win` builds a portable x64 executable with `SHA256SUMS-windows.txt`. You can run it on Windows or Linux.
- `npm run build:win:installer` builds the optional NSIS installer. It requires Windows or a working Wine installation on Linux. The standard release downloads exclude this installer.
- `npm run release:check` verifies that the version, lockfile, and CI tag match.
- `npm run release:publish -- --dry-run` verifies the packages and generates a local release preview.

Find downloads and installation instructions in the [main README](../README.md). To create a GitHub release, follow the [release guide](../docs/RELEASING.md).

## Saving and recovery

Disabling autosave stops scheduled saves after typing pauses. Switching documents, creating a new document, returning to the home screen, or closing the window still waits for pending changes to be saved. If a save fails, the editor stays open and displays the error. Use **Save As** to create a copy when there is a conflict. When a save finishes, any edits made after that save began remain unsaved.

The app queues writes and replaces the original using a temporary file on the same volume. It compares the previously read content with the file on disk to detect external edits or deletion. Other apps can still access the file, so avoid editing it elsewhere while a write is in progress.

Drafts without a file path appear under **Recover a draft** after restart, including drafts stored under keys from earlier versions. Deleting the active file keeps its contents as a draft and prevents further writes to the deleted path. If moving an item to the trash fails, the app leaves it in place.

Version history is stored in `fountain_history` under `userData`. The app serializes operations and replaces metadata atomically. If the index is corrupted, the app copies it to `meta.corrupt.*.json` and rebuilds it from the saved versions. When a document's path changes, the app transfers its history and keeps the original as a recovery copy.

Drafts and versions are stored locally **without encryption**. Keep an external backup.

## Markdown and export

Documents containing tables, images, or HTML open in Markdown source mode to preserve syntax that Tiptap's visual editor schema cannot represent. The visual editor supports code blocks containing HTML examples.

The app generates PDFs from Markdown in an isolated session with a Content Security Policy. The session excludes raw HTML, JavaScript, network access, and remote images. DOCX and ODT exports preserve breaks, nested lists, tables, and links. They represent images with descriptions and links and display a notice during export.

Version comparison runs in a worker that can be canceled and uses matrices with bounded size. Very large changes are shown in blocks.

## Architecture

- **Main process.** `src/main/index.js` initializes services. `windowManager.js` manages windows and waits for the editor before closing them. `ipc.js` applies the checks in `ipcSecurity.js` to every channel that receives renderer messages.
- **Files and export.** `fileIpc.js` coordinates native file pickers, permissions managed by `fileService.js`, and exports. `storage.js` queues writes and replaces files atomically. `historyManager.js` maintains saved versions. The exporters receive Markdown and share document preparation through `exportSource.js`.
- **Workspace search.** `workspaceSearchIpc.js` manages one cancellable search per window. `workspaceSearch.js` walks authorized files and delegates Markdown analysis to a worker.
- **Preload.** `src/preload/index.js` exposes specific methods and subscriptions that callers can unsubscribe from.
- **Renderer.** `App.jsx` connects the home screen to the editor. Hooks manage preferences, folders, and navigation. `lib/documentSession.js` tracks revisions and serializes saves independently of React. The editor uses its own hooks for shortcuts, history, and typewriter scrolling.
- **Styles.** `src/renderer/src/assets/main.css` defines the stylesheet order. Rules are grouped by screen or interface feature.

Access is granted only through native file and folder pickers. The app stores these permissions in `authorized-paths.json`. After upgrading from a version that lacked this file, you may need to reopen your files and folders once using the picker. The app reports an error for disconnected or inaccessible folders. Documents are limited to 10 MiB, and the file browser reports depth and size limits as well as partial errors.

## Security and distribution

All windows run in a sandbox. Leave `--no-sandbox` unset when troubleshooting installation issues. Linux requires user namespaces or a correctly installed sandbox helper. Native startup was verified on Linux with the sandbox enabled.

The release includes an AppImage and a deb package for Linux and a portable executable for Windows, all for x64. Packages contain the compiled code, production dependencies, and the GPL license. The packages share icons from `resources/`. Download updates manually from GitHub Releases. The Windows executable is unsigned by default. The release guide covers optional signing, and the repository contains no signing credentials. Test the packages on their target systems before publishing.

GitHub Actions runs a reproducible install, project checks, `npm audit --omit=dev`, and `npm audit --audit-level=high`. Production dependency vulnerabilities or high or critical advisories stop the workflow. The workflow avoids forcing incompatible major-version upgrades. Tests use temporary directories. Keep them pointed at test files.
